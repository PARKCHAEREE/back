### 3️⃣ 이상 탐지 상태값 명세 정합성 정리

#### 3.1 Anomaly 엔티티 기본값 변경 ✅

```java
// 변경 전
@Column(columnDefinition = "VARCHAR(50) DEFAULT 'DETECTED'")
private String status; // DETECTED, ACKNOWLEDGED, RESOLVED

// 변경 후
@Column(columnDefinition = "VARCHAR(50) DEFAULT 'OPEN'")
private String status; // OPEN, ACKNOWLEDGED, RESOLVED
```

#### 3.2 레거시 DETECTED 상태 자동 정규화 ✅

서비스 계층에서 응답 시 자동 변환:

```java
private String normalizeStatus(String status) {
    if (status == null || status.isBlank() || "DETECTED".equals(status)) {
        return "OPEN";
    }
    return status;
}
```

- DB에 이미 `DETECTED`로 저장된 데이터도 응답 시 `OPEN`으로 변환
- AI 저장 로직(`AiIntegrationService`)도 `OPEN`으로 통일

#### 3.3 발전소 소유권 검증 AnomalyService 적용 ✅

기존 목록 조회에도 소유권 검증 추가:

    validatePlantAccess(powerPlantId, userId); // 소유권 확인 추가

## 🏗️ 아키텍처 개선사항

### 이상 탐지 API 전체 흐름

```
클라이언트
    │
    ├─ GET /anomalies/{eventId}
    │       ↓
    │   JWT 인증 → userId 추출
    │       ↓
    │   AnomalyService.getAnomalyDetail(plantId, eventId, userId)
    │       ├─ PowerPlantRepository: 소유권 확인 (없으면 404)
    │       ├─ AnomalyRepository: 이벤트 단건 조회 (없으면 404)
    │       └─ normalizeStatus(): DETECTED → OPEN 정규화
    │       ↓
    │   ApiResponse<AnomalyDto>
    │
    └─ PATCH /anomalies/{eventId}/status
            ↓
        @Valid 요청 검증 (OPEN|ACKNOWLEDGED|RESOLVED만 허용)
            ↓
        AnomalyService.updateAnomalyStatus(plantId, eventId, userId, status)
            ├─ 소유권 확인
            ├─ status 업데이트
            └─ RESOLVED면 resolvedAt 설정, 아니면 null
            ↓
        ApiResponse<UpdateAnomalyStatusResponse>
```

### 상태값 체계

```
AI 탐지 결과 저장
    └─ status = "OPEN" (이전: DETECTED)

DB 조회 시
    └─ "DETECTED" 값 발견 → normalizeStatus() → "OPEN" 반환

상태 전이 규칙
    OPEN → ACKNOWLEDGED → RESOLVED
    RESOLVED → OPEN (되돌리기 가능, resolvedAt 초기화)
```
